# Simple Live V5：自动排版、多路声音与多画面全屏

多画面按实际添加的 1～9 个直播间和窗口比例自动排版，增减画面会重新铺满。移除了固定的 2/3/4/9 画面按钮和底部常驻说明。

- 从关注添加时显示“直播中 / 未开播 / 查询中 / 状态未知”，直播中的主播优先显示，并提供刷新状态按钮。查询失败不会直接显示未开播。
- 每个新画面默认静音，包括从普通直播间或浮窗接入的第一路。点击每格喇叭单独开启或关闭，允许同时开启多路声音；顶部按钮可全部静音。
- 点击全屏按钮或按 F11 进入多画面全屏。工具栏闲置 3 秒后隐藏，移动鼠标或点击画面重新显示，Esc 退出。双击单个画面仍可放大/还原。
- 弹幕默认关闭，在每格菜单中开启“顶部弹幕”。仅占视频顶部不超过约 15% 的区域，高度最多 30 像素，约一到两行；降低不透明度，每秒最多接收一条用于显示，满轨道直接丢弃。弹幕不遮挡点击操作，也不显示礼物和特效。
- 画面小于 320×240 时自动隐藏弹幕；被其他画面放大遮住、暂停、关闭或退出多画面时释放对应弹幕连接。放大后恢复。沿用用户已有的关键词屏蔽设置。
- 修复弹幕 WebSocket 在连接握手过程中关闭后仍重新启用心跳的时序问题。

## 使用

完整解压 Windows x64 压缩包，保留 DLL 与 data 文件夹，运行 `simple_live_app.exe`。进入方式：首页网格按钮，或“我的 → 多画面”。正式版本共用原有用户配置，一次运行一个正式版本；替换前退出旧版。

退出多画面会停止全部多画面播放。普通直播间的 APP 内浮窗继续保留。

## 验证范围与已知问题

本版回归检查包含独立声音、默认静音、1～9 路布局覆盖、状态区分、弹幕鼠标穿透、延迟连接关闭与原有播放恢复/浮窗测试。Windows 实播、画面截图和进程退出检查结果随发布包提供，功能报告与原生进程退出结果分开记录。

此前发现的抖音空房间数据解析失败、部分斗鱼连接约 300 秒断开，以及历史 Windows 原生内存访问崩溃，仍需各自定位处理。本次更新不将它们标记为已修复。一次退出检查通过仅说明该次测试正常退出，不代表所有旧故障已排除。

此次本机测试已重复复现正常关闭窗口时的原生访问异常 `0xc0000005`，位置为 `CoreMessaging.dll`。这是故障发生位置，不等于已确定根因。因此 V5 以预览版发布，功能验证与退出崩溃分别报告。

源码与 Dart AOT/资源在 Debian 构建；Windows 启动器及原生插件 DLL 沿用现有 Simple Live 1.11.4 文件，未重新编译原生组件。项目遵循 GPL-3.0，保留上游与第三方声明。
